Steerholm is one daemon and one CLI: the daemon is the plane your agents connect to
and act on, and the `holm` CLI is how you control it. Installing sets up both and
starts the daemon running as you.

## One-line install

The install script downloads pre-built binaries, registers a per-user background daemon that runs as you, and starts it. No admin rights, no Python or package manager required.

<CodeGroup>

```bash Linux / macOS
curl -fsSL https://steerholm.ai/install.sh | bash
```

```powershell Windows
irm https://steerholm.ai/install.ps1 | iex
```

</CodeGroup>

This installs the `holm` CLI and starts the daemon's HTTP MCP endpoint at `http://127.0.0.1:4767/mcp`.

## What the install script does

1. Downloads the latest release binaries for your platform
2. Installs `holm` to `~/.local/bin` (Linux/macOS) or `%LOCALAPPDATA%\steerholm\bin` (Windows)
3. Registers a per-user background daemon that runs as you (no admin required):
   - **Linux**: systemd user service
   - **macOS**: launchd user agent
   - **Windows**: a logon Scheduled Task
4. Starts the daemon on `http://127.0.0.1:4767/mcp`

The daemon starts at login. On Linux and macOS it also restarts if it crashes; on
Windows, a crashed daemon stays down until your next sign-in or `holm start`.

You can also download binaries manually from the [GitHub Releases](https://github.com/steerholm/steerholm/releases) page.

## Verify

```bash
holm status
```

You should see `Daemon is running.` Its endpoint is `http://127.0.0.1:4767/mcp`.

## Upgrade

Update to the latest release in place:

```bash
holm update
```

It downloads the new release's installer, verifies it, and runs it: the daemon is
stopped, the binary replaced, your stored data brought up to the new version's
format, and the daemon started again. Servers, agents, keys and grants carry over.

Use `holm update --check` to see whether a newer version is available without installing, and `holm version` to print the installed version. See the [CLI reference](/reference/cli) for all options.

<Note>
  Updating **from 0.1.0 or 0.1.1** on Linux or macOS ends with `Terminated`
  (exit code 143) right after `Updated Steerholm to …`. That is the installer
  ending the previous version's updater once the new version is in place, so
  that none of the old program runs on; the update has succeeded. `holm version`
  shows the new version.
</Note>

## Development setup

For contributing or local development:

```bash
git clone https://github.com/steerholm/steerholm.git
cd steerholm
uv venv
source .venv/bin/activate
uv pip install -e ".[dev]"
```

This installs in editable mode — changes to the source take effect immediately.

<Note>
  A source install never runs the installer, so it never runs the schema
  migration the installer performs. If Steerholm refuses to start because the
  state on disk is an older schema, bring it up to date with:

  ```bash
  holm migrate
  ```

  It is hidden from `holm --help` deliberately — for a normal install the
  installer runs it, and nobody should have to think about it.
</Note>

```bash
# Run tests
pytest

# Run the daemon locally
holm serve
```
