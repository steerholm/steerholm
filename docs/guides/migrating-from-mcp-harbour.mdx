---
title: Migrating from MCP Harbour
description: Move an existing MCP Harbour setup to Steerholm — stop the old daemon, install, and re-add your servers and agents.
---

Steerholm is the successor to MCP Harbour. The command is now `holm` (was
`harbour`), config lives in `~/.steerholm` (was `~/.mcp-harbour`), and the daemon
service, keyring entries, and access-key prefix all changed with it.

Nothing carries over automatically, so migrating is a short manual pass: stop the
old daemon, install Steerholm, and re-create your servers and agents. Your old
data is left untouched, so you can fall back or clean it up once you're confident.

<Warning>
  `harbour update` won't bring you to Steerholm — it reports you're already up to
  date, because Steerholm ships as a separate product rather than an MCP Harbour
  update. Follow the steps below to move over.
</Warning>

<Note>
  Re-adding an agent issues a **new access key** (`steer_sk_…`). The old
  `harbour_sk_…` keys stop working, so every connected client needs its new key —
  plan a moment to update client configs.
</Note>

<Steps>
  <Step title="Write down your current setup">
    Your servers, agents, and grants all live in the old config file. Read it so
    you know what to recreate:

    <CodeGroup>
    ```bash Linux / macOS
    cat ~/.mcp-harbour/config.json
    ```

    ```powershell Windows
    type $env:APPDATA\mcp-harbour\config.json
    ```
    </CodeGroup>

    Note each server's `--command` or `--url`, and which agents are granted which
    tools. (If the old daemon is still running, `harbour list servers` and
    `harbour list agents` show the same thing.)
  </Step>

  <Step title="Stop and remove the MCP Harbour daemon">
    This frees port `4767` for Steerholm. If you still have the MCP Harbour
    uninstaller, running it does all of this; otherwise:

    <CodeGroup>
    ```bash Linux
    systemctl --user stop mcp-harbour
    systemctl --user disable mcp-harbour
    rm -f ~/.config/systemd/user/mcp-harbour.service
    systemctl --user daemon-reload
    ```

    ```bash macOS
    launchctl unload ~/Library/LaunchAgents/dev.mcp-harbour.daemon.plist
    rm -f ~/Library/LaunchAgents/dev.mcp-harbour.daemon.plist
    ```

    ```powershell Windows
    schtasks /End /TN MCPHarbour
    schtasks /Delete /TN MCPHarbour /F
    ```
    </CodeGroup>
  </Step>

  <Step title="Install Steerholm">
    Follow the [installation guide](/getting-started/installation) — the one-liner
    installs the `holm` binary and starts the daemon.

    <CodeGroup>
    ```bash Linux / macOS
    curl -fsSL https://steerholm.ai/install.sh | bash
    ```

    ```powershell Windows
    irm https://steerholm.ai/install.ps1 | iex
    ```
    </CodeGroup>

    Confirm it's up with `holm status`.
  </Step>

  <Step title="Re-add your servers and agents">
    Recreate each server, agent, and grant with the new verb-first CLI, using the
    notes from step 1:

    ```bash
    holm add server filesystem --command "npx -y @modelcontextprotocol/server-filesystem /home/you"
    holm add agent my-agent            # prints a new steer_sk_… key — save it
    holm grant my-agent filesystem --tool "read_*"
    ```

    See [Connect an agent](/guides/connect-an-agent) and
    [Managing access](/guides/managing-access) for the full command set.
  </Step>

  <Step title="Reconnect your clients">
    Update each MCP client with its new access key and the endpoint
    `http://127.0.0.1:4767/mcp`, then verify the setup:

    ```bash
    holm list servers
    holm list agents
    ```
  </Step>

  <Step title="Clean up the old install (optional)">
    Once everything works, remove the leftover MCP Harbour data and binaries:

    <CodeGroup>
    ```bash Linux / macOS
    rm -rf ~/.mcp-harbour
    rm -f ~/.local/bin/harbour
    ```

    ```powershell Windows
    Remove-Item -Recurse -Force $env:APPDATA\mcp-harbour
    Remove-Item -Recurse -Force $env:LOCALAPPDATA\mcp-harbour
    ```
    </CodeGroup>

    The old access-key hashes also linger in your OS keyring under the services
    `mcp-harbour` and `mcp-harbour-control`; delete those entries from your
    keychain / credential manager if you want a fully clean slate.
  </Step>
</Steps>

<Note>
  If `holm status` reports the daemon isn't running right after install, the most
  likely cause is the old MCP Harbour daemon still holding port `4767` — recheck
  step 2, then see [Troubleshooting](/guides/troubleshooting).
</Note>
