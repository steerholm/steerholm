---
title: Error Codes
description: How Steerholm reports a refused or failed request to an agent.
---

Steerholm refuses or fails a request for one of two reasons:

| Code | Name | Meaning |
|------|------|---------|
| `-31001` | `AUTHORIZATION_DENIED` | The request violates the agent's policy |
| `-31002` | `SERVER_UNAVAILABLE` | The MCP server that would answer it is down or not reachable |

## Tool calls

A refused or failed **tool call** comes back as a normal MCP tool result marked
`isError: true`, with the reason as its text — the form MCP uses for errors the
model should see. The code itself is not part of the result; the message says
which case it is:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "content": [
      { "type": "text", "text": "Tool 'git_commit' on server 'git' is not allowed." }
    ],
    "isError": true
  }
}
```

## Other requests

Any other request Steerholm refuses — for example listing tools for an agent
that has no usable identity — returns a JSON-RPC error with the code, and the
name in `data.error_type`:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -31001,
    "message": "Agent 'ci' has no usable identity; it cannot be granted access. Re-add the agent.",
    "data": { "error_type": "AUTHORIZATION_DENIED" }
  }
}
```

## Behavior

### AUTHORIZATION_DENIED

Returned when:
- The agent calls a tool not in its policy
- The agent calls a tool with arguments that violate an argument policy
- The agent calls a tool that no server it has access to provides

The agent **must not retry** the same operation — the denial is authoritative.
Every denial is in the [audit log](/reference/audit-log) as `denied`, with the
reason.

### SERVER_UNAVAILABLE

Returned when the MCP server process is not running, has stopped answering, or
cannot be reached — including when the tool is not found on the servers that did
answer but a server the agent may use did not.

The agent **may retry** — the daemon restarts failed servers, so the server may
be back shortly. These are in the audit log as `error`, not `denied`.
