title: holm CLI
description: Control-plane commands for managing servers, agents, and access.
---

The `holm` CLI is your **[control plane](/concepts/control-plane)** — where you add
agents and servers and govern what each agent can reach. Agents don't run it; they
act on the action plane over the daemon's [MCP endpoint](/reference/mcp-endpoint).

Commands read verb-first — `holm <verb> <resource> [name]`.

The verbs are `add`, `modify`, `remove`, `list`, `show`, `grant`, `revoke`, and
`rotate`;
the resources are `server` and `agent`. Alongside them: [`log`](#audit-log) reads
what your agents did, daemon lifecycle is `start` / `stop` / `status` / `serve`,
and `version` / `update` round out the surface.

## Servers

Servers are the MCP servers you want agents to reach through Steerholm. Adding a
server registers it with the daemon, which handles starting and stopping the
server processes.

### holm add server

Register a new MCP server. Provide `--command` for stdio servers or `--url` for
HTTP servers (not both); the server type is inferred. Pass config or secrets to a
stdio server with `--env` (repeatable).

```bash
# Stdio server
holm add server git \
  --command "uvx mcp-server-git"

# Stdio server with environment variables (e.g. a DB connection string)
holm add server db \
  --command "uvx postgres-mcp" \
  --env "DATABASE_URI=postgresql://user:pass@localhost/app"

# HTTP server
holm add server remote-api --url "http://localhost:8000/mcp"
```

| Argument / Option | Required | Description |
|---|---|---|
| `<name>` | Yes | Unique name for the server |
| `--command` | One of | Full command to launch a stdio server |
| `--url` | One of | URL of a streamable HTTP server |
| `--env` | No | `KEY=VALUE` environment variable for a stdio server (repeatable) |

<Note>
  `--env` names must be letters, digits, `_`, `-`, or `.` and can't start with a
  digit (the Kubernetes/Docker rule, for cross-platform portability); a repeated
  name is an error. Values may contain anything, including `=`.
</Note>

### holm modify server

Change a server without removing it. Only what you name changes: `--env` merges
into the existing variables and `--unset` removes them.

```bash
# Point it at a different command
holm modify server git --command "uvx mcp-server-git --repository /srv/app"

# Add one variable, drop another
holm modify server db --env "DATABASE_URI=postgresql://..." --unset OLD_VAR

# Switch it to a remote server
holm modify server api --url "http://localhost:9000/mcp"
```

| Option | Description |
|---|---|
| `--command` | New launch command (stdio) |
| `--url` | New server URL (streamable HTTP) |
| `--env` | Set `KEY=VALUE` (repeatable; merges with what is there) |
| `--unset` | Remove an environment variable by name (repeatable) |

The server keeps its **id** and every agent's **grants** — that is what makes this
different from removing and re-adding it, which would create a different server
with no grants. The daemon restarts the server process with the new spec, so
in-flight calls to it fail; agent sessions to Steerholm itself are unaffected.

<Warning>
  Because grants survive, repointing a server at a different command hands every
  agent that was granted access to the old one the same access to the new one.
  `holm modify server` names those agents so the transfer is never silent.
</Warning>

<Note>
  Switching transport clears the state belonging to the old one: moving to
  `--url` drops the launch command and its environment variables, and moving to
  `--command` drops the URL. The command warns before it does so.
</Note>

### holm remove server

Remove a server from Steerholm.

```bash
holm remove server git
```

### holm list servers

Show all servers with their transport type and live status (state, uptime, and
tool count when the daemon is running).

```bash
holm list servers
```

### holm show server

Show a server's id and configuration, its live status, the tools it provides, and
which agents have been granted access to it. The id is what `holm log --server`
takes to isolate one server's history from a reused name.

```bash
holm show server git
```

## Agents

An agent has a name and an **access key**. The access key is what the agent uses
to authenticate — Steerholm resolves the agent from the key, so agents cannot
impersonate each other.

### holm add agent

Add an agent and generate its access key. The key is shown once and cannot be
retrieved later — store it when it's printed.

```bash
holm add agent my-agent
```

### holm list agents

Show all agents and their access-key prefixes.

```bash
holm list agents
```

### holm show agent

Show an agent: its id and access-key prefix, everything it can reach (server →
tools → argument constraints), and how to connect it with its key. The id is what
`holm log --agent` takes to isolate one agent's history from a reused name.

```bash
holm show agent my-agent
```

### holm rotate agent

Generate a new access key for an agent, keeping all of its grants. The previous
key stops working immediately — update the agent's config in its tool with the new
key.

```bash
holm rotate agent my-agent
```

### holm remove agent

Remove an agent, its access key, and its policy. The key is revoked immediately.

```bash
holm remove agent my-agent
```

## Access (grants)

An agent's policy is default-deny: with no grants it has zero access. Grants are
additive — each `grant` adds a rule.

### holm grant

Grant an agent access to a server's tools.

```bash
holm grant <agent> <server> [--tool PATTERN] [--args POLICIES...]
```

**Allow all tools on a server:**

```bash
holm grant my-agent git
```

**Allow a specific tool:**

```bash
holm grant my-agent git --tool "git_log"
```

**Restrict by argument value (glob):**

```bash
holm grant my-agent git --tool "git_log" --args "repo_path=/home/user/projects/**"
```

**Restrict by argument value (regex):**

```bash
holm grant my-agent database --tool "query" --args "sql=re:^SELECT\s.*"
```

**Multiple argument restrictions on one tool:**

```bash
holm grant my-agent database --tool "query" --args "sql=re:^SELECT\s.*" "db=production"
```

| Option | Default | Description |
|---|---|---|
| `--tool` | `*` | Tool name or glob pattern |
| `--args` | — | Argument policies: `arg=pattern` (glob) or `arg=re:pattern` (regex) |

A glob pattern without wildcards is an exact match. An argument policy applies
only when the tool call actually provides that argument.

### holm revoke

Remove an agent's access to a server. With `--tool` it removes only that tool
grant; without it, the agent's entire access to the server is removed. `--tool`
matches the exact pattern you granted (e.g. `git_diff*`), not a glob expansion of
it — so revoke the same pattern you used in `grant`.

```bash
# Remove one tool grant
holm revoke my-agent git --tool "git_log"

# Remove all access to the server
holm revoke my-agent git
```

| Option | Default | Description |
|---|---|---|
| `--tool` | — | Revoke only this tool grant; omit to revoke all access to the server |

## Audit log

Steerholm records every tool call an agent makes through it — which agent, which
server, which tool, and whether policy allowed it, denied it, or the server
failed. See [Audit log](/reference/audit-log) for the record format and where it
is stored.

### holm log

Show recorded decisions. Reads the files directly, so it works with the daemon
stopped.

```bash
holm log                                    # the 50 most recent calls
holm log --status denied                    # only what was refused
holm log --server git --agent coding-agent  # one agent, on one server
holm log --follow                           # watch calls as they happen
```

| Option | Default | Description |
|---|---|---|
| `--number`, `-n` | `50` | Show the most recent N entries (`0` for all) |
| `--agent` | — | Only this agent, by name **or** id |
| `--server` | — | Only this server, by name **or** id |
| `--status` | — | Only this outcome: `allowed`, `denied`, or `error` |
| `--follow`, `-f` | — | Keep printing entries as they are recorded (Ctrl-C to stop) |

Filters combine, so `--server git --status denied` shows what was refused on one
server. With `--follow`, recent history prints first and then new decisions
appear as they happen.

<Note>
  Names are reusable: removing and re-adding an agent or a server gives a
  different one the same name, so a name filter can span both. `--agent` and
  `--server` also accept the immutable id that `holm show agent` / `holm show
  server` print, which isolates one of them — and `holm log` says so when a name
  covers more than one.
</Note>

### holm log config

Show how much history the log keeps, and where it lives. Read-only.

```bash
holm log config
```

```
Audit log
  Files:         ~/.steerholm/events-*.jsonl
  Max files:     5
  Max age:       unlimited
  Disk ceiling:  50 MB (10 MB per file)
```

### holm log set

Change how much history the log keeps. Both limits apply — a log file is removed
once it is past the file count **or** older than the age limit.

```bash
holm log set --max-age-days 30    # keep a month of history
holm log set --max-files 20       # allow more history on disk
holm log set --max-age-days 0     # no age limit (the file count still applies)
```

| Option | Default | Description |
|---|---|---|
| `--max-files` | `5` | How many log files to keep (`0` = no limit) |
| `--max-age-days` | `0` | Delete log files older than this (`0` = no limit) |

Changes take effect on a running daemon without a restart. Segment size is fixed
at 10 MB and is not configurable — changing it would leave existing files at the
old size.

## Daemon

The daemon is the long-running process that exposes the Streamable HTTP MCP
endpoint, manages server connections, and enforces policies. Installation
registers it as a per-user background daemon that runs as you (no admin required)
and starts automatically at login.

### holm start

Start the daemon via the platform's per-user service manager (systemd `--user`, a
launchd agent, or a Windows logon Scheduled Task).

```bash
holm start
```

### holm stop

Stop the daemon. All active agent sessions are disconnected.

```bash
holm stop
```

### holm status

Check whether the daemon is currently running.

```bash
holm status
```

### holm serve

Run the daemon in the foreground instead of as a service. Useful for debugging —
logs go to stderr.

```bash
holm serve
holm serve --host 0.0.0.0 --port 5000
```

| Option | Default | Description |
|---|---|---|
| `--host` | `127.0.0.1` | Host to bind |
| `--port` | `4767` | Port to bind |

<Warning>
  Steerholm binds to loopback (`127.0.0.1`) by default. Binding to a non-loopback
  host like `0.0.0.0` exposes the endpoint — and its tool access — to your
  network, and access keys travel as Bearer tokens over plain HTTP. Only do this
  on a trusted network, ideally behind a TLS-terminating reverse proxy.
</Warning>

## Version & updates

### holm version

Print the installed Steerholm version. `holm --version` does the same.

```bash
holm version
```

### holm update

Update Steerholm in place from a GitHub release (the latest by default). It
downloads the release for your platform, verifies it against the published
checksums, and runs the official install script.

```bash
holm update               # install the latest release
holm update --check       # report whether an update is available, without installing
holm update --tag vX.Y.Z  # install a specific release tag
holm update --yes         # install without the confirmation prompt
```

| Option | Description |
|---|---|
| `--check` | Report whether a newer version is available without installing |
| `--tag` | Install a specific release tag instead of the latest |
| `--force` | Reinstall even if the selected version isn't newer |
| `--yes`, `-y` | Install without confirmation |
