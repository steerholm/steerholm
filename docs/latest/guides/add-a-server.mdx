---
title: Add a server
description: Register an MCP server with Steerholm and confirm it's running.
---

An MCP server is how a resource is connected to the plane: the git MCP server for
your repositories, the filesystem MCP server for a folder, a database MCP server
for a database, or an internal service's own MCP endpoint. You add it to Steerholm
once; from then on you decide which agents may reach that resource, and on what
rules, by [granting access](/guides/managing-access).

<Note>
  Registering a server exposes nothing on its own. No agent can reach it until you
  grant access — Steerholm is default-deny.
</Note>

## Register the server

Steerholm runs two kinds of MCP server: **stdio** servers it launches from a
command, and **remote** servers it connects to over HTTP. Give `--command` for one
or `--url` for the other — the type is inferred.

```bash
# Stdio — Steerholm launches the process
holm add server git --command "uvx mcp-server-git"

# Remote — Steerholm connects to an already-running HTTP server
holm add server remote-api --url "http://localhost:8000/mcp"
```

Pass configuration or secrets to a stdio server with `--env` (repeatable) — for
example a database connection string:

```bash
holm add server db \
  --command "uvx postgres-mcp" \
  --env "DATABASE_URI=postgresql://user:pass@localhost/app"
```

`holm show server` masks env values, so secrets don't print back.

## Confirm it's running

`list servers` shows every server with its transport and live status; `show server`
adds the tools it provides and which agents have been granted access:

```bash
holm list servers
holm show server git
```

A healthy stdio server shows `running` with a tool count. Right after you add or
change it, or after the daemon starts, it shows `starting` for a few seconds —
longer the first time an `npx` or `uvx` server downloads its package. If it
never comes up, see
[Troubleshooting](/guides/troubleshooting).

## Add more than one

Connect as many resources as you need:

```bash
holm add server filesystem --command "npx -y @modelcontextprotocol/server-filesystem ~/docs"
holm add server internal-api --url "http://localhost:9000/mcp"
```

An agent sees only the tools its grants allow, on each server it has been granted.
Setting those rules is covered in [Managing access](/guides/managing-access).

## Change a server

Change a server's command, URL, or environment in place. It keeps its id and every
agent's grants, and the daemon restarts it with the new settings:

```bash
holm modify server git --command "uvx mcp-server-git --repository /srv/app"
holm modify server db --env "DATABASE_URI=postgresql://..." --unset OLD_VAR
```

## Remove a server

Removes the server from Steerholm, stops its process (for stdio servers), and
revokes every agent's grants on it — the command names the agents affected:

```bash
holm remove server git
```

Adding a server again under the same name creates a new server with no grants. To
change a server without losing them, use `holm modify server` instead.
